<h2>v1.0.2 - Waystone naming fix</h2>

<h3>Fix</h3>
<ul>
<li><strong>Unnamed waystones</strong>: the naming retry used <code>level.getServer().execute(...)</code>, which runs synchronously and immediately when already called from the server thread — all 10 retries were consumed instantly without letting real server ticks pass, so waystones generated on top of the towers could end up without a name. The retry now runs one attempt per real server tick via <code>ServerTickEvent.Post</code>.</li>
</ul>

<h3>Notes</h3>
<blockquote>No config or generation changes. Existing worlds and configs are fully preserved.</blockquote>
